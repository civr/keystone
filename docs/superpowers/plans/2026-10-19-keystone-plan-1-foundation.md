# Keystone Plan 1 — Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A deploy-and-go Keystone: `docker compose up -d` → setup wizard → sign in with AD password + passkey → style-A home page with app tiles → Instellingen where every security measure is tunable, images published to GHCR.

**Architecture:** Go service `keystone-core` (API, AD auth, sessions, WebAuthn, settings, audit) behind `keystone-web` (Caddy: serves hashed static assets, proxies everything else to core). Postgres holds config/passkeys/apps/audit; Valkey holds sessions and rate-limit counters. A one-shot `keystone-init` container generates all secrets into a dedicated volume. SvelteKit (static) UI in Dutch.

**Tech Stack:** Go 1.27 · chi v5 · pgx v5 · go-redis v9 (Valkey) · go-ldap/ldap v3 · go-webauthn/webauthn · golang.org/x/crypto/argon2 · testcontainers-go · SvelteKit 2 + Svelte 5 (adapter-static) · Vitest · Caddy 2 · Postgres 17 · Valkey 8 · GitHub Actions → GHCR.

**Spec:** `docs/superpowers/specs/2026-10-19-keystone-design.md`

**Later plans (out of scope here):** 2 SAML IdP + Bastion · 3 OIDC provider + Nimbus generic OIDC · 4 `keystone-ldap` + Jellyfin · 5 `keystone-gate` + Home Assistant component + native-app bypass · 6 Kluis + UniFi tile, key rotation, LDAP-client settings, login notifications. Apps in this plan are link tiles (`protocol = "link"`); later plans add protocols to the same `apps` table.

## Global Constraints

- Single owner: only the AD account chosen in setup (`owner.username`) may sign in; any other AD account → `403`, audited.
- No `.env` required. All secrets generated by `keystone-init` into volume `keystone_secrets` mounted read-only at `/run/keystone` in core. Files: `db_password`, `valkey_password`, `session_key` (32 B), `data_key` (32 B). Never stored in Postgres.
- Every security setting is editable in the GUI (Instellingen → Beveiliging); none require env vars. Changes require step-up (passkey within `login.step_up_minutes`) and write an audit entry with old/new values.
- Defaults (spec §4/§7/§12): session 720 h sliding; trusted device 90 days; passkey required; passkey-only on trusted device; user verification `required`; recovery codes 10.
- Speed targets: home page first render < 300 ms on LAN; home-page JS < 100 kB gzip (CI-enforced); session lookup p95 < 5 ms.
- UI language: Dutch. Style A (spec §6): radial gradient bg (light + dark), glass search (backdrop-blur), squircle tiles with soft shadow, system font stack `-apple-system, "SF Pro Text", "Segoe UI Variable", "Segoe UI", system-ui, sans-serif`, spring motion, `prefers-reduced-motion` respected, works on phone width.
- Greeting by local hour: 06–12 "Goedemorgen", 12–18 "Goedemiddag", 18–24 "Goedenavond", 00–06 "Goedenacht", followed by AD `givenName` (fallback `displayName`, then username).
- Cookies: `ks_session`, `ks_pending`, `ks_device`; `HttpOnly`, `SameSite` from settings (default `Lax`), `Secure` when `public_url` is https.
- Container images: `ghcr.io/civr/keystone-core`, `ghcr.io/civr/keystone-web`, `ghcr.io/civr/keystone-init`; linux/amd64 + linux/arm64; Go images distroless static nonroot.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Locking yourself out via network settings** — saving `network.admin_cidrs` or `network.login_cidrs` that exclude the requester's current IP must be rejected with a clear message; a CLI `keystone-core reset-network` (run via `docker compose exec`) clears both lists. Tests in Task 3 and Task 9.
2. **AD down or slow** — login must answer within `ad.timeout_seconds` (default 5) with "AD is niet bereikbaar", never hang; the emergency account is then offered. Tests in Task 5 and Task 8.
3. **Username variants** — `THIJS`, `HOME\thijs`, `thijs@home.lan` all normalize to sAMAccountName `thijs` and match the owner case-insensitively. Test in Task 5.
4. **Spoofed `X-Forwarded-For`** — client IP for rate limits/allowlists only trusts XFF hops that come from Caddy plus admin-listed trusted proxies; a client-supplied XFF from the internet is ignored. Test in Task 6.
5. **Shortening session settings / revoking** — existing sessions obey a shorter `session.duration_hours` and revocation on their very next request. Test in Task 4.

### Task 8: Sign-in API

**Files:**
- Create: `internal/httpapi/auth.go`, `internal/httpapi/auth_test.go`

**Interfaces:**
- Consumes: Tasks 3–7.
- Flow (spec §4):
  1. `POST /auth/password`: per-IP and per-account limits; locked → 429 `{"error":"locked","retry_after":s}`; normalize username; not owner → 403 `not_allowed` (audited, same timing as wrong password); `ErrUnavailable` → 503 `{"error":"ad_unavailable","emergency":<enabled>}`; success → `ks_pending` (5 min) with `password_ok`; response `next = "passkey"` or `"register_passkey"` if no passkeys.
  2. `POST /auth/passkey/begin|finish` with `password_ok` pending → session (`LastFullAuthAt=now`) + set `ks_device` (new device id or same).
